# UK Rail Viz

An MBTA Viz–style interactive dashboard for the UK rail network — Marey diagram of train trajectories, station traffic heatmaps, congestion & delay horizon charts, commute scatterplots, and a live train-position overlay — powered by precomputed JSON derived from Network Rail **Darwin** data, served as a static site on Render's free tier.

This is a **port** of the [MBTA Viz](https://mbtaviz.github.io/) project (by Mike Barry & Brian Card, MIT license) adapted for Great Britain's rail network. The rendering code follows the exemplar's patterns; the data pipeline and UK-specific adapters are original work.

**Scope (v1):** An eastern-region proof of concept covering **c2c, Greater Anglia, selected CrossCountry, and selected Great Northern** routes — four corridors out of London's terminals.

## How it works

### Architecture

A single long HTML page, one `<section>` per visualization. All sections load their data **in parallel at page load** (the only lazy path is per-origin commute rollups, fetched on drag). Everything is SVG — no canvas, no map tiles. The "map" is a hand-drawn schematic built from `spider.json` coordinates + `station-network.json` links.

### Data pipeline

```
Darwin S3 snapshots ──┐
HSP historical actuals┤
TRUST live positions ─┤
ORR station usage ────┤──→ tools/etl/ ──→ data/*.json ──→ dist/
NaPTAN coordinates ───┘
```

The ETL is confined to **GitHub Actions** (Render's build runs offline on committed `data/`). The refresh pipeline runs on a schedule, fetches Darwin feeds, derives JSON artifacts, runs smoke tests, builds `dist/`, and commits the data back. Render auto-deploys on push to `prod`.

### Asset strategy

All JS and CSS assets are content-hashed by `tools/build.js` (e.g. `main.6ccebf1e.css`) and references in `index.html` are rewritten automatically. This enables immutable caching with `max-age=31536000, immutable` on `/assets/*`.

| Section | What it shows | JS file | Data files |

| **Header** | Animated schematic map glyph with moving train dots | `header.js` | `station-network.json`, `spider.json`, `marey-trips.json` |

## Commands

| Command | What it does |
|---|---|
| `npm install` | Install dev dependencies |
| `npm run fixtures` | Generate realistic placeholder data in `data/` (for local dev without live feeds) |
| `npm run collect` | Fetch Darwin S3 snapshots + HSP data (requires credentials) |
| `npm run derive` | Transform raw data into JSON artifacts (requires `data/` from collect) |
| `npm run smoke` | Validate data artifact shapes |
| `npm test` | Fixtures → smoke → build → unit tests (the full pipeline) |
| `npm run build` | Assemble `dist/`, hash assets, enforce §8 budgets (fails on overrun) |
| `npm run pipeline` | collect → derive → smoke → build (the full ETL chain) |
| `npm run dev` | Start a local dev server on port 3000 serving `dist/` |

### Running locally

```bash
npm install
npm run fixtures        # generate placeholder data
npm run build           # assemble dist/
npm run dev             # serve on http://localhost:3000
```

For live data, set the required environment variables (see `.env.example`) and run `npm run pipeline`.

## Deployment

The site deploys to Render's free tier as a static site. The branch model:

- **`main`** — integration branch (PRs merge here)
- **`prod`** — deploy branch (Render auto-deploys only this; fast-forward only from `main`)

To deploy: `git push origin main:prod`

The `render.yaml` blueprint configures:
- Brotli-compressed static serving
- `Cache-Control: public, max-age=31536000, immutable` on `/assets/*` (hashed files)
- `Cache-Control: public, max-age=900` on `live.json` and `station-frequency.json` (frequently refreshed)
- `Cache-Control: public, max-age=3600` on other data JSON
- `Cache-Control: public, max-age=300` on everything else

## Known limitations

- **No per-minute passenger counts** — the UK has no turnstile equivalent; station traffic uses service frequency as a proxy.
- **No multi-year trends** — v1 shows a rolling recent window, not historical comparisons.
- **No self-archived TRUST history** — historical actuals come from HSP, not from a continuously running STOMP consumer.
- **Live positions are last-reported only** — no prediction, no dwell time.
- **No platform-level geometry** — platform numbers are not rendered on the schematic.
- **Northern Ireland not covered** — NaPTAN covers England, Scotland, Wales only.
- **No map tiles** — the "map" is a hand-drawn SVG schematic, not a geographic map.

See SPEC.md §10 for the full non-goals and data gaps.
